| 项目 | 决策 |
|---|---|

| V1 小组件 | 取消时钟、天气和其他小组件，仅保留书签功能 |

| 排期 | 4–6 个工作日，不含商店审核 |
| 当前状态 | 已通过用户审查，进入编码 |

### 精简原因

1. 书签是不可妥协的核心功能，其他功能不应挤占书签体验的开发资源；
2. 直接使用 Chrome 原生书签树，避免复制数据、冲突和额外备份系统；
3. CSS 自定义组件比完整 UI 库更容易控制视觉风格和首屏体积；
4. 固定 CSS Grid 代替自由拖拽网格，降低交互复杂度并保证布局稳定；
5. 天气、壁纸、搜索等能力后移，等书签主页获得验证后再增加。

## 第二部分：产品方案

### 2.1 产品目标

owntab V1 只解决一个核心问题：

> **打开新标签页后，用一个干净、好看的界面浏览和编辑 Chrome 书签栏。**

产品不是 iTab/WeTab 的全功能替代品，V1 不追求小组件生态，而是先把「书签展示、书签编辑、书签同步、视觉体验」做好。

### 2.2 V1 硬约束

- 原生 Chrome 书签栏作为唯一数据源，不复制一份书签数据库；
- 支持展示和编辑：打开、创建、重命名、修改 URL、移动、删除；
- 默认进入 Chrome 的 **Bookmarks bar / 书签栏**；
- 支持切换到「其他书签」和「移动书签」；
- 浏览器书签栏和主页之间保持事件驱动的最终一致性；
- 不需要账号、后端、埋点或云同步；
- 优先保证界面层次、留白、交互反馈和小尺寸适配。

### 2.3 V1 功能范围

| 模块 | V1 范围 |
|---|---|
| 新标签页 | 使用 `chrome_url_overrides.newtab` 替换 Chrome 新标签页 |
| 书签根目录 | 默认显示 Chrome 的 Bookmarks bar，可切换其他根目录 |
| 书签浏览 | 文件夹进入、返回、面包屑、书签列表、文件夹列表、空状态 |
| 书签编辑 | 新建书签、新建文件夹、重命名、修改 URL、移动（弹出目标文件夹选择器，选择后确认；V1 不支持拖拽排序）、删除 |
| 书签打开 | 点击书签在当前标签打开（与 Chrome 原生书签栏行为一致）；不申请 `tabs` 权限；设置中可切换为新标签打开 |
| 原生同步 | 监听书签创建、删除、修改、移动、同级排序事件 |
| 主题 | 浅色、深色、跟随系统三种模式 |
| 基础设置 | 默认根目录、列表密度、是否新标签打开、主题切换 |
| 视觉反馈 | 加载、保存中、保存成功、错误、删除确认、空目录状态 |

### 2.4 V1 明确不做

以下功能全部后移，避免分散书签体验的开发精力：

- 天气；
- 壁纸和必应每日图；
- 聚合搜索和搜索建议；
- 网址导航卡片；
- 时钟和其他小组件；
- 自由拖拽网格；
- WebDAV、账号、云同步；
- JSON 配置备份；
- AI、热搜、股票、待办、日历。

> V1 仍可保留浏览器地址栏搜索能力。主页不额外实现搜索框，避免重复浏览器功能。

### 2.5 V1.1 候选

只有 V1 的书签浏览和编辑稳定后，才评估：

- 搜索本地书签；
- 书签拖拽排序；
- JSON 导出；
- 简单时钟；
- 可选背景图。

## 第三部分：界面方案

### 3.1 页面结构

采用单页、居中、低干扰的书签工作台：

```text
┌────────────────────────────────────────────┐
│ owntab                         主题  设置   │  顶部工具栏
├────────────────────────────────────────────┤
│ 书签栏 / 其他书签 / 移动书签                │  根目录切换
│ 首页 / 产品 / 工具                          │  面包屑
├────────────────────────────────────────────┤
│                                            │
│  文件夹       文件夹       书签             │
│  名称         名称         标题             │  主内容区
│                                            │
│  书签         书签         新建             │
│  书签         书签         文件夹           │
│                                            │
├────────────────────────────────────────────┤
│  共 24 项                         快捷操作  │  状态栏
└────────────────────────────────────────────┘
```

### 3.2 视觉方向

目标是「安静、清晰、像一个认真做过的桌面工具」，不做花哨营销页。

- 页面最大宽度：`1120px`，左右留白充足；
- 内容区使用固定列数的 CSS Grid，不引入自由拖拽网格；
- 卡片圆角不超过 `8px`，边框细、阴影弱；
- 浅色主题以白色、浅灰和一个青绿色强调色为主；
- 深色主题使用深灰背景，不使用大面积渐变和紫色光晕；
- 书签卡片高度稳定，标题最多两行，超出显示省略号；
- 文件夹和书签使用不同但一致的图标系统；
- 操作按钮优先使用图标，鼠标悬停提供 tooltip；
- 所有危险操作使用确认弹窗，不使用浏览器原生 `confirm()`；
- 交互状态用轻量 toast、按钮状态和局部提示表达，不弹全屏提示。

### 3.3 书签显示模式

V1 只实现一种主模式，减少复杂度：

- 当前根目录的直接子项以卡片列表展示；
- 文件夹显示文件夹图标，点击进入；
- 书签显示 favicon、标题和域名；favicon 加载失败时使用域名首字母 + 彩色圆片占位（色板见第四部分 §2.3），按域名字符 hash 固定取色，保证同一域名始终显示同一颜色；
- 右上角提供「新建书签」和「新建文件夹」；
- 每项提供一个明确的更多操作按钮：编辑、移动、删除；
- 子目录通过面包屑返回，不在一个页面递归展开整棵树。

这样同时避免了树状界面拥挤、嵌套滚动和大规模递归渲染。

### 3.4 响应式与可访问性

- 桌面宽度大于 `900px`：四列书签卡片；
- `600px–900px`：三列；
- 小于 `600px`：两列，并允许页面滚动；
- 卡片、编辑按钮、面包屑均可通过键盘访问；
- 书签卡片具备可见 focus 状态；
- 删除和移动操作提供清晰的键盘路径；
- 不把颜色作为唯一状态提示；
- 长标题、长域名和空目录必须有稳定布局。

### 3.5 视觉验收标准

编码完成后必须人工检查：

1. 1440×900、1280×720、1024×768 三个桌面尺寸不出现重叠或横向溢出；
2. 书签标题最多两行，不撑高卡片；
3. 书签数量为 0、1、20、200 时布局都稳定；
4. 文件夹名称、书签名称、URL 很长时不破坏按钮位置；
5. 浅色、深色、系统主题切换不闪烁；
6. 加载、错误、删除确认和空目录都有明确视觉状态；
7. 键盘 Tab 顺序符合页面视觉顺序；
8. 首屏不会出现明显白屏或布局跳动。

## 第四部分：视觉设计规范

### 4.1 设计原则

| # | 原则 | 含义 |
|---|---|---|
| 1 | **内容是主角** | 书签本身是信息，UI 只负责组织，不抢戏 |
| 2 | **克制但不冷漠** | 不用花哨效果，用微动效、排版节奏、状态反馈体现质感 |
| 3 | **层次清晰不累** | 一眼看清结构，不需要大脑解析 |
| 4 | **日夜都舒适** | 暗色主题不是「把白变黑」，是真正适配夜间的独立设计 |

### 4.3 字体系统

#### 字体栈

```css
font-family:
  system-ui, -apple-system, BlinkMacSystemFont,
  'PingFang SC', 'Hiragino Sans GB',
  'Segoe UI', Roboto,
  'Microsoft YaHei', sans-serif;
```

> 说明：`system-ui` 作为首选（Chrome 56+ 支持），中文字体提前于西文字体，确保中英文混排时中文字形统一由 `PingFang SC` / `Microsoft YaHei` 渲染，避免 Windows 上中文意外回退到 `Segoe UI`。

### 4.6 动效

#### 时长

| Token | 值 | 用途 |
|---|---|---|
| `--duration-fast` | `150ms` | 悬停、颜色过渡 |
| `--duration-normal` | `200ms` | 卡片上浮、淡入淡出 |
| `--duration-slow` | `300ms` | 主题切换、弹窗出现 |

#### 缓动

```css
--ease-out: cubic-bezier(0.25, 0.46, 0.45, 0.94);
--ease-in-out: cubic-bezier(0.42, 0, 0.58, 1);
```

#### 具体动效

| 场景 | 效果 |
|---|---|
| 卡片悬停 | `translateY(-2px)` + 阴影增强，`200ms ease-out` |
| 主题切换 | 全局颜色过渡 `300ms ease-in-out` |
| 弹窗出现 | `opacity 0→1` + `scale 0.96→1`，`200ms ease-out` |
| 弹窗关闭 | `opacity 1→0`，`150ms ease-out` |
| Toast 出现 | `translateY(10px)→0` + `opacity 0→1`，`200ms` |
| 骨架屏 | 灰色块 `pulse` 动画，`1.5s infinite` |
| 新建卡片出现 | `opacity 0→1` + `translateY(4px)→0`，`200ms` |

## 第五部分：技术方案

### 5.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + TypeScript | 组件边界清晰，适合单页工具 |
| 扩展构建 | WXT | 自动生成 MV3 newtab override |
| UI 样式 | CSS Variables + 少量自定义组件 | V1 不引入 Naive UI，减少包体与视觉约束 |
| 数据源 | `chrome.bookmarks` | 原生书签作为唯一事实来源 |
| 设置存储 | `chrome.storage.local` | 只存主题、根目录、列表密度等少量设置 |
| 图标 | Chrome `_favicon` API | 不缓存 base64 图标 |
| 校验 | zod | 校验用户输入和书签编辑表单 |
| 测试 | Vitest + 手动浏览器验收 | 覆盖书签数据转换和操作错误处理 |

### 5.2 权限范围

V1 只申请：

```json
{
  "permissions": ["bookmarks", "storage", "favicon"]
}
```

V1 不申请：

- `tabs`；
- `history`；
- `<all_urls>`；
- 天气、壁纸相关 host permissions；
- `unlimitedStorage`。

说明：`bookmarks` 权限会产生「读取和更改书签」的安装提示。商店描述和隐私政策必须说明：书签只在本机读取和修改，不上传到 owntab 服务器。

### 5.3 书签 API 架构

建议由 background service worker 统一封装 API：

```text
BookmarksWidget
   │ runtime message
   ▼
background service worker
   │ chrome.bookmarks API
   ▼
Chrome 原生书签树
   │ bookmarks events
   ▼
background service worker
   │ runtime message 广播
   ▼
所有打开的 newtab 页面
```

background 负责：

- 初始读取书签根节点；
- `getChildren()` 按目录读取子项；
- create、update、move、removeTree；
- 统一捕获 API 错误；
- 广播书签变化。

newtab 页面负责：

- 展示当前目录；
- 打开编辑弹窗；
- 发送操作请求；
- 收到事件后刷新当前目录；
- 不复制完整书签树到 `storage.local`。

### 5.4 书签根目录规则

默认根目录为 Chrome 返回的 Bookmarks bar 节点，不根据中文或英文标题判断。

启动时通过 `chrome.bookmarks.getTree()` 获取根树，根据 Chrome 返回的根节点标识选择：

- Bookmarks bar；
- Other bookmarks；
- Mobile bookmarks。

设置中保存 `rootId`，如果节点不存在或浏览器返回结构变化，则回退到 Bookmarks bar。

### 5.5 书签编辑规则

| 节点 | 改标题 | 改 URL | 新建子项 | 删除 |
|---|---:|---:|---:|---:|
| 根目录 | 否 | 否 | 是 | 否 |
| 文件夹 | 是 | 否 | 是 | 是，二次确认 |
| 书签 | 是 | 是 | 否 | 是，二次确认 |

额外规则：

- 删除文件夹必须明确提示会递归删除所有子项；
- URL 只允许 `http` 和 `https`；
- 空标题禁止提交；
- API 失败时保留弹窗内容并显示可读错误，不假装成功；
- 不在 UI 内先做不可回滚的乐观更新，以浏览器事件作为最终结果。

### 5.6 事件同步

必须处理：

- `onCreated`：新增书签或文件夹；
- `onRemoved`：删除书签或文件夹；
- `onChanged`：标题或 URL 变化；
- `onMoved`：跨目录移动；
- `onChildrenReordered`：同一目录内排序变化；
- `onImportBegan` / `onImportEnded`：导入大量书签时暂停频繁刷新。

同步语义定义为：

> **事件驱动的最终一致性同步**，不承诺「毫秒级」；事件触发后刷新受影响目录，多个 newtab 页面最终显示相同结果。

### 5.7 数据保存边界

书签数据不复制进 owntab 配置，不进入 `storage.local`，也不进入 JSON 备份。

`storage.local` 只保存：

```ts
interface SettingsState {
  theme: 'light' | 'dark' | 'auto';
  rootId: string;
  density: 'comfortable' | 'compact';
  openInNewTab: boolean;
}
```

导出设置时必须明确提示：

> 原生 Chrome 书签由浏览器独立管理，不包含在 owntab 配置导出中。请使用 Chrome 自带的书签导出功能备份书签。

## 第八部分：V1.1 扩展功能规格（2026-10-18）

> 依据用户要求，跳过外部设计工具，在 V1 稳定架构之上继续递进开发生产力扩展功能。保持“无后端、无第三方服务器依赖、Chrome 原生数据为唯一源”原则。

### 8.1 扩展配置模型兼容

存储结构平滑扩展，原 `Settings` 结构保持向上兼容，缺失字段默认填充：

```typescript
interface SettingsV11 extends Settings {
  view: 'grid' | 'list';            // 默认 'grid'
  showSearchBar: boolean;           // 默认 true
  searchEngine: string;             // 默认 'google' (bing/baidu/duckduckgo/github)
  showClock: boolean;               // 默认 false
  pinnedIds: string[];              // 默认 [] (最多 24 个)
}
```

### 8.2 全局搜索与快捷命令面板 (SearchPalette & SearchBar)

- **快捷键**：全局 `Cmd/Ctrl + K` 呼出命令面板模态框，`Esc` 关闭并复原焦点。
- **检索算法**：加权检索 `scoreQuery` 覆盖标题全词、前缀、包含及字符顺序匹配，优先展现全书签树匹配项。
- **搜索引擎直达**：当无书签匹配或用户直接按 Enter 提交时，调起选定搜索引擎在新标签页（或当前标签页）检索。

### 8.3 常用书签置顶栏 (PinnedBar)

- **交互机制**：卡片右键/更多菜单中新增“固定到常用”/“取消固定”选项；
- **展示方式**：主内容区上方渲染紧凑水平胶囊栏，支持快捷进入与快速取消；
- **持久化**：仅存储书签节点 ID，节点被删除时自动滤除失效 ID。

### 8.4 视图切换 (View Modes)

- 支持 `grid`（经典网格卡片）与 `list`（高密度单行列表）双重视图；
- 列表视图保留 favicon、标题单行省略、域名副文本与悬浮操作；
- 快捷切换按钮置于工具栏，切换状态持久化至 `chrome.storage.local`。

### 8.5 书签健康维护工具 (MaintenancePanel)

- **死链检测**：在设置/维护抽屉中按需发起连接性探测（支持并发控制，返回有效/重定向/失效状态）；
- **重复书签合并**：基于标准化 URL 聚合重复节点，提示所属文件夹路径，支持一键定位或清理；
- **隐私与沙箱安全**：所有计算与网络探测直接由本地执行，绝不向第三方上传书签数据。

## 第十部分：V1.2 审查修复（2026-10-21）

### 10.1 打开链接与最近使用

- 普通点击由应用层统一处理：先写入 `recent` 再跳转，避免页面卸载导致写入丢失；
- `⌘/Ctrl/Shift/Alt` 点击仍走浏览器原生行为（新标签打开等），但同样记录最近使用；
- 打开协议白名单为 `http` 与 `https`，其余协议（`javascript:`、`data:`、`file:`、`chrome:`、`ftp:` 等）不提供可点击链接。

### 10.2 本地存储序列化

- Chrome 的 storage API 会把 Vue 的 reactive Proxy 数组序列化成 `{"0": ...}` 对象；
- 所有写入 `chrome.storage.local` 的值必须先经 `toPlain()` 转为纯 JSON；
- 读取端兼容旧的 `{"0": ...}` 结构，自动还原为数组。

### 10.3 删除二次确认

- 维护面板的重复书签与失效链接删除，同样走统一的 `DeleteConfirm` 弹窗；
- 取消删除返回维护面板，已删除的行立即从列表移除。

### 10.4 搜索与重复判定

- 搜索评分改为真正的子序列匹配：查询字母必须按顺序出现，`Glider` 不再匹配 `git`；
- 搜索索引在树或标签变化时重建一次，输入时只做过滤，避免每次按键全树遍历；
- 重复网址归一化只对协议与主机名做小写，路径与查询串保留大小写。

### 10.5 其他

- `domain()` 对非 http/https 协议一律返回空，特殊协议书签显示「特殊网址」；
- 版本号提升到 `1.2.0`。
